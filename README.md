# 矩形纸张贯通裁切排样（Paper Cutter）

供小型印刷作坊使用的 Web 应用：输入母纸尺寸、刀缝宽度、张数上限、搜索状态数上限以及
各类成品（长、宽、份数、能否旋转），搜索出满足**全部份数**的排样方案，输出：

- **逐张排样图**（SVG，红虚线标出每一刀，数字为全局下刀顺序，旋转件标注 ↻）；
- **按执行顺序排列的贯通式裁切步骤**（每一刀的方向、刀线坐标、起止点、刀缝）；
- **实际成品数**（逐类与需求核对）。

找到**任意可行方案即返回，不保证最优**。

## 工艺约束（求解器严格保证）

- 尺寸均为正整数毫米，刀缝为非负整数毫米；
- **每一刀都沿直线贯穿当前所在的矩形余料**（guillotine / slicing cut），不能只切一段；
- 相邻成品之间扣除刀缝宽度；
- 成品不得重叠、不得越界；
- 成品只有勾选「允许旋转」时才能旋转 90°；
- 不要求超产：实际成品数恰好等于各需求份数。

## 搜索结果的三种状态

| 状态 | 含义 | 可否导出 |
| --- | --- | --- |
| `feasible` | 找到可行方案，已保存 | 可以 |
| `infeasible` | **已穷尽搜索**：在给定张数上限（含刀缝损耗）内确实无解 | 无方案可导出 |
| `budget` | **搜索预算耗尽**：访问的状态数达到「搜索状态数上限」，**不能据此声称无解**；可调大上限后重新搜索 | 无方案可导出 |

## 输入版本与方案失效

- 每次「保存输入」都会产生新版本号（v1、v2…）与输入指纹（参数 SHA-256 的前 16 位）。
- **保存输入后再修改任一参数并保存（哪怕只是搜索预算），旧方案立即失效并被删除。**
- 裁切单导出页会显著标明**输入版本号与输入指纹**；对失效/不存在的方案导出会被拒绝（HTTP 409），
  避免车间拿着与当前参数不一致的旧裁切单施工。
- 非法输入（非整数、0/负数、布尔值冒充足数、重名、空成品清单等）会被服务端拒绝，**不会保存**，
  也不能用于搜索。

## 一键启动（Docker Compose）

需要 Docker 与 Docker Compose v2（`docker compose` 子命令）。

```bash
docker compose up -d --build
```

启动后访问：

- 应用地址：<http://localhost:8000>
- 裁切单导出（在首页搜出可行方案后可用）：<http://localhost:8000/export>

停止：

```bash
docker compose down            # 保留数据卷（方案/输入不丢）
docker compose down -v         # 同时删除数据卷
```

数据保存在 Docker 卷 `cutter-data` 的 `/data/cutter.db`（SQLite，含 WAL 文件）。

## 仅用 Docker（不用 Compose）

```bash
docker build -t paper-cutter .
docker run -d --name paper-cutter -p 8000:8000 \
  -v paper-cutter-data:/data paper-cutter
```

## 本地直接运行（开发）

需要 Python 3.11+。

```bash
pip install -r requirements.txt
export CUTTER_DB=$(pwd)/data/cutter.db   # 可选，默认 /data/cutter.db
python -m flask --app app.wsgi run --host 0.0.0.0 --port 8000
# 或：gunicorn --bind 0.0.0.0:8000 app.wsgi:app
```

数据库表在应用启动时自动创建（`CREATE TABLE IF NOT EXISTS`），无需手工初始化。

## 输入字段与取值范围

| 字段 | 说明 | 范围 |
| --- | --- | --- |
| `master_w` / `master_h` | 母纸长 / 宽 (mm) | 1–10000 的正整数 |
| `kerf` | 刀缝宽度 (mm) | 0–1000 的非负整数 |
| `max_sheets` | 张数上限 | 1–1000 的正整数 |
| `max_states` | 搜索状态数上限 | 1–100,000,000 的正整数 |
| 成品 `w` / `h` | 成品长 / 宽 (mm) | 1–10000 的正整数 |
| 成品 `qty` | 份数 | 1–1,000,000 的正整数 |
| 成品 `rotatable` | 是否允许旋转 90° | `true` / `false` |
| 成品 `name` | 名称 | 非空、≤40 字符、不重复（最多 200 种） |

## HTTP 接口

| 方法与路径 | 作用 |
| --- | --- |
| `GET /` | 浏览器界面 |
| `GET /api/state` | 当前输入（含版本/指纹）与当前方案 |
| `PUT /api/inputs` | 校验并保存输入（自增版本、清除旧方案）；非法返回 400 且不写库 |
| `POST /api/solve` | 基于**已保存**的输入搜索；返回 `feasible` / `infeasible` / `budget` |
| `GET /api/solution` | 当前已保存方案（可能为 `null`） |
| `GET /export` | 裁切单 HTML（可直接浏览器打印为 PDF）；无方案/方案失效返回 409 |

## 裁切单怎么用

1. 首页填参数 →「保存输入」→「开始搜索」。
2. 查看逐张排样图：每张母纸内，成品按颜色区分，红虚线就是刀，数字是**全局下刀顺序**。
3. 图下方有序列表给出每一刀：方向（竖切/横切）、刀线坐标（从母纸左上角 `(0,0)` 起算，
   x 向右、y 向下，单位 mm）、在当前余料上的起止点、刀缝宽度。
4. 打开「导出裁切单」可打印 / 另存为 PDF；页首带输入版本号与指纹，参数变更后必须重新搜索。

## 算法说明

搜索分两层：

1. **快速构造层**（不消耗搜索状态预算）：先尝试几种确定性可行解构造——
   best-fit 角点填充（先竖切/先横切两种偏好）与等高货架（shelf）排样。
   每条构造结果都要通过一道**独立运行时自检**（成品不重叠/不越界/朝向合法，
   且逐刀模拟余料切分，确认每一刀都贯穿当时的余料）；自检不过直接丢弃。
   因此快速层只会“命中或放弃”，绝不会产出错误方案。常见规整作业通常在此层毫秒级返回。
2. **完整穷尽层**（消耗搜索状态预算）：在每个矩形余料左上角放一块成品，先竖切或先横切
   把 L 形剩余区域切成两个矩形递归填充；子矩形允许整块留空以消化不可避免的浪费，
   母纸不允许整张贴空。该结构可枚举所有 slicing 排样，所以搜索树自然穷尽即代表
   该排样类下无解；状态计数用于预算控制，达到预算立即停止并报告「预算耗尽」。

刀的**执行顺序**由切分树的前序遍历给出（先在当前余料上下刀，再递归处理切出的各块余料），
导出的步骤编号可直接照做。

> 说明：本工具以「找到可行方案」为目标，**不做全局最优**（不最小化用纸数或废料）。
> 快速构造层可能比穷尽层用更多纸；若快速构造未能在张数上限内完成，则交由穷尽层在
> 预算内继续搜索。

## 测试

```bash
pip install pytest
python -m pytest tests/ -q
```

- `tests/test_solver.py`：可行方案的独立几何校验（越界、重叠、旋转限制），并用区域切分模拟
  验证**每一刀都贯穿当前余料**；含刀缝精确贴合、无解判定、预算语义与 12 组参数化随机实例。
- `tests/test_api.py`：非法输入不入库、bool/float 拒绝、版本自增与失效、导出 409、
  预算耗尽可重试等端到端测试。
